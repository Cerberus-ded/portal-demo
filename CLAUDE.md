# Портал: сайт салона отделочных материалов (Димитровград)

Демо-версия сайта салона «Портал» для показа заказчику: главная (`index.html`) и каталог (`katalog.html`).
Сайт статический, без сервера и без фреймворков: чистые HTML, CSS и JavaScript. Публикуется через GitHub Pages
из корня ветки `main` (файл `.nojekyll` обязателен).

Общение с владельцем, тексты сайта, коммиты и описания PR пишутся по-русски.

## Как устроен репозиторий

| Путь | Что это | Править руками? |
|---|---|---|
| `index.html`, `katalog.html` | Собранные страницы, их отдаёт GitHub Pages | Нет, это результат сборки |
| `lord/`, `zodchij/`, `andora/`, `chameleon/`, `adema/`, `raznye/`, `torex/` | Пакеты фото дверей по фабрикам: `covers.json` (обложки коллекций), `s-<коллекция>.json` (мелкие фото), `l-<коллекция>.json` (крупные), у Торекса ещё `k-<серия>.json` (комплектация) и `colors.json` (цвета серий). Фото лежат внутри как base64 WebP | Нет, собираются |
| `x1/seek.json` | Данные поиска для главной | Нет, собирается |
| `photos/` | Фото главной в двух размерах (`k-*-<ширина>.webp`) | Да, это исходник и результат одновременно |
| `fonts/` | Шрифты сайта (Cormorant Garamond и Manrope, кириллица и латиница, лицензия SIL OFL). Грузятся с самого сайта, не с Google: адрес посетителя никуда не уходит до согласия на cookie | Да, это исходник и результат одновременно |
| `r31/` | Исходники страниц: `home.body.html`, `cat.body.html`, `cat.js` (приложение каталога), `*.head.html` (title, description, Open Graph, разметка LocalBusiness), `legal.json` (реквизиты салона и номер Метрики), `about.json` (описания коллекций от салона вместо текстов фабрик, ключ — код коллекции) | Да |
| `src31/` | Общие стили и скрипты: `base.css`, `home.css`, `catalog.css`, `seek.js` (поиск), `calc.js` (калькулятор метража), `admin.js` (админка), `cookies.js` (окно cookie и Метрика), `demo.js` (хранилище демо в браузере, `PortalDemo`) | Да |
| `web/<фабрика>/*.json` | Данные коллекций, собранные с сайтов и прайсов фабрик: названия, описания, характеристики, модели. `web/lord/price.json`, `web/torex/kit/*.json` из прайсов фабрик, БЕЗ цен | Да, но лучше через скрипты в `tools/` |
| `tools/` | Сборка, сбор данных с сайтов фабрик, обработка фото и PDF, проверки в браузере | Да |
| `tsconfig.json` | Только для линтера deslop-please: какие скрипты корня он проверяет. Сайт без TypeScript и без сборки JS | Да, если появится новая папка со скриптами |

Сами фотографии дверей (`web/<фабрика>/s/`, `l/`, `png/`, `src/`, `swatch/`, картинки `web/torex/kit/<серия>/`) в git не хранятся:
это около 120 МБ исходников, они лежат только на компьютере владельца. Поэтому полная пересборка пакетов фото возможна
только там. В облаке можно менять исходники, данные и скрипты и пересобирать страницы из уже собранных пакетов фото (см. «Сборка», `--packs`).

## Сборка

Из корня проекта (там, где лежат `r31/`, `src31/`, `tools/`, `web/`, `photos/`):

```bash
node tools/build31.mjs . _build/site31          # каталог, пакеты фото, поиск; рядом пишет _build/glavnaya31.src.html
python -I tools/build_demo31.py _build/site31 _build/glavnaya31.src.html _build/demo
# перенести в корень: сначала убрать старые пакеты фабрик (папки с covers.json) и поиск,
# иначе пакеты удалённых и переименованных коллекций останутся на сайте и в git; затем скопировать сборку
for d in */; do [ -f "${d}covers.json" ] && rm -r "$d"; done; rm -rf x1
cp -r _build/demo/. .
```

`build31.mjs` и `build_demo31.py` удаляют папку вывода целиком перед записью. Корень проекта, папку выше него и папку с исходниками
или `.git` они удалять откажутся (`build_demo31.py` ещё и папку со сборкой, которую читает). Всё равно давайте им отдельную папку внутри `_build/`.
После переноса `git add -A` подхватит и удалённые пакеты.

Без исходных фото (в облаке) страницы собираются из пакетов, которые уже лежат в корне репозитория: добавьте `--packs .`

```bash
node tools/build31.mjs . _build/site31 --packs .
python -I tools/build_demo31.py _build/site31 _build/glavnaya31.src.html _build/demo
# сборка читает пакеты из корня, поэтому старые пакеты убирать только после неё, затем перенести как выше
for d in */; do [ -f "${d}covers.json" ] && rm -r "$d"; done; rm -rf x1
cp -r _build/demo/. .                           # пакеты фото выйдут байт в байт такими же, git покажет только страницы и x1/seek.json
```

В этом режиме меняются страницы, тексты, данные коллекций и поиск, но не фото. Если в данных появилась модель, которой
нет в собранных пакетах (новое фото), сборка остановится с ошибкой «no photo in the built packs»: такое собирается только на компьютере владельца.

README.md, CLAUDE.md и `.claude/` сборка не трогает.

## Проверки

Проверки запускают сайт в headless Chrome через `puppeteer-core`. Путь к браузеру берётся из переменной `CHROME`
(по умолчанию Chrome под Windows). В облаке:

```bash
npm i --prefix /tmp/nm puppeteer-core@23      # один раз, PUPPETEER_SKIP_DOWNLOAD=1
CHROME=/opt/pw-browsers/chromium node tools/mobile37.mjs . /tmp/shots /tmp/nm 360,390,414 demo
```

- `tools/mobile37.mjs`: телефонная версия экран за экраном (ничего не шире экрана, кнопки не меньше 40 px, текст не обрезан, ошибки страницы). Главная проверка перед каждым PR.
- `tools/doors32.mjs`, `tools/lord31.mjs`: каталог дверей по коллекциям, крупный просмотр.
- `tools/demo31.mjs`: демо как статический сайт: заявка, экран менеджера, сброс демо.
- `tools/adm31.mjs`: коллекция, добавленная через админку.
- `tools/look.mjs`, `tools/shot.mjs`: снимок страницы или её части, чтобы посмотреть глазами.
- `python -I tools/audit.py . [фабрика ...]`: фото дверей (поля, пропорции, мелкие, дубли). Нужны исходные фото, только на компьютере владельца.

### Структура кода: deslop-please

[deslop-please](https://github.com/Bor4brn/deslop-please) (порт для JavaScript и TypeScript; [оригинал](https://github.com/deterministic-machines/deslop-please)
проверяет только Rust) ищет плохо устроенный код: модули, которые используют друг друга по кругу (`module-cycle`, `tangle`),
поля класса, с которыми работают снаружи (`field-leak`), модули, которые показывают наружу больше функций, чем прячут (`shallow-module`),
папки больше 15 файлов и файлы длиннее 2000 строк (`wide-directory`, `long-file`). Два проекта: скрипты корня
(`tools/*.mjs`, `src31/*.js`, `r31/*.js`, их список в `tsconfig.json`) и `.ts`/`.js` приложения `app/`. Файлы `.svelte` он не читает.
В облаке:

```bash
cargo install --git https://github.com/Bor4brn/deslop-please --rev acb918de --locked deslop-please   # один раз
npm i --prefix /tmp/nm @sourcegraph/scip-typescript@0.5.2                                              # один раз, индексатор
(cd app && npm ci)                    # без пакетов app/ проверяется только корень
node tools/deslop.mjs /tmp/nm         # код выхода 0: ошибок нет, 1: есть ошибки
```

На 28.11.2026 ошибок нет и allow-файла нет. Ближе всех к пределу `r31/cat.js`: 1829 строк из 2000.

## Правила проекта

- Цен на сайте нет: салон показывает, что можно заказать. Из прайсов фабрик берём состав и комплектацию, никогда не цены.
- Фото взяты с сайтов фабрик временно, до разрешений и своих снимков салона. Страницы закрыты от поисковиков (`noindex, nofollow`): не снимать, пока владелец не скажет.
- Заявки, экран менеджера и админка в демо работают только в браузере посетителя (localStorage и IndexedDB через `PortalDemo`), ничего никуда не отправляется. Не добавлять отправку данных наружу без решения владельца.
- Персональные данные по 152-ФЗ: Яндекс Метрика грузится только после согласия в окне cookie. Тексты согласия, политики и сведения о продавце берут реквизиты из `r31/legal.json`; пока поля пустые, на сайте видна подсказка.
- Сайт в первую очередь для телефона: любое изменение вёрстки проверять `mobile37.mjs` на 360, 390 и 414 px. Страница никогда не должна прокручиваться вбок.
- Адресов `claude.ai` в собранном сайте быть не должно (сборка это проверяет).
- Адрес сайта для превью ссылок (Open Graph) задан в `SITE_URL` в `tools/build_demo31.py`. Переедет сайт на свой домен: поменять там и пересобрать.
- Работа идёт в ветках и через PR, в `main` напрямую не пушим. Коммиты короткие, по-русски, о том, что изменилось для посетителя («Торекс: без плашки „Скоро в продаже“ в опциях»).
- Каждая пересборка добавляет в историю git десятки МБ base64-пакетов. Не пересобирать и не коммитить пакеты фото без нужды.
- Перед PR, где менялись скрипты (`tools/`, `src31/`, `r31/*.js`, `app/`), запускать `node tools/deslop.mjs` (см. «Проверки»).
  Ошибки deslop-please исправлять по существу, а не механическими перестановками, которые их только прячут
  (перенести функцию в другой файл, склеить модули, разрезать файл на куски по номеру строки):
  - `module-cycle` и `tangle`: какой слой абстракции здесь задуман? Какой модуль на каком слое должен быть?
  - `field-leak` и `shallow-module`: зачем эти поля и функции вообще есть? Как их используют? Можно ли спрятать их за узким интерфейсом?
    Не чинить утечки по одной, а пересобрать интерфейс целиком.
  - `long-file` и `wide-directory`: делить по смыслу, так чтобы новый модуль прятал свою часть работы за узким интерфейсом.
  - В описании PR показать схему «как было» и «как предлагаю», чтобы владелец понял перестройку.
  - Не глушить ошибки allow-файлом (`--allow`, `--update-allow`) без решения владельца.

## Агенты

В `.claude/agents/` лежат помощники для этого проекта: `frontend-dev` (вёрстка и скрипты), `catalog-data` (данные фабрик и фото),
`qa-tester` (проверки в браузере), `code-reviewer` (ревью изменений перед PR), `content-seo` (тексты, юридические страницы, SEO).
