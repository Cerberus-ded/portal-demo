# Портал: сайт на SvelteKit

Версия сайта салона «Портал» на Svelte 5 и SvelteKit 3, из которой вырастет рабочий сайт. Демо-версия в корне репозитория
(`index.html`, `katalog.html`, GitHub Pages) остаётся как есть и живёт отдельно: эта папка её не трогает.

## Что уже есть

| Адрес | Страница | Откуда перенесено |
|---|---|---|
| `/` | Главная: разделы, акции, работы, о салоне, фабрики, контакты | `r31/home.body.html` |
| `/katalog/` | Обзор каталога | `r31/cat.js`, `renderOverview` |
| `/katalog/<раздел>/` | Раздел: фильтры, сортировка, сетка коллекций. Фильтры в адресе: `?brand=Лорд&style=Классика&sort=name` | `renderFacets`, `renderGrid` |
| `/katalog/<раздел>/<коллекция>/` | Коллекция: модели, крупный просмотр, характеристики, комплектация Торекса, заявка. `?m=3` открывает с выбранной моделью | `renderDetail`, `buildViewer`, `kitSection` |
| `/korzina/` | Корзина и заявка на все позиции | `renderCart` |
| `/zayavki/` | Экран менеджера: заявки и их статус | `renderInbox` |
| `/dokumenty/soglasie/`, `politika/`, `cookie/` | Юридические документы с реквизитами из `r31/legal.json` | `DOCS` в `r31/cat.js` |

Поиск (кнопка с лупой, `/` или Ctrl+K) работает на всех страницах: это `src31/seek.js` демо-версии, перенесённый модулем.
Окно cookie и Яндекс Метрика после согласия: `src31/cookies.js`. Старые ссылки демо вида `katalog.html#vhodnye-TOREX-DELTA-PRO`
открывают новые адреса, если зайти с ними на `/katalog/`.

У каждой коллекции теперь свой адрес и своя готовая HTML-страница (172 коллекции, 185 страниц), а не `#` внутри одной страницы.

Чего ещё нет: админки (акции, работы и новые коллекции салон пока меняет только в демо), калькулятора метража
(понадобится с плиткой и полами), отправки заявок салону (см. ниже).

## Правила проекта здесь

- Цен нет нигде: в данных их нет, на страницах только «цена по запросу».
- Пока нет разрешений фабрик на фото, сайт закрыт от поисковиков: `<meta name="robots" content="noindex, nofollow">` на каждой странице
  и `static/robots.txt` с `Disallow: /`. Переключатель один: `INDEXING` в `src/lib/site.ts`, включать только по слову владельца.
- Заявки и статусы менеджера лежат только в браузере посетителя (`src/lib/orders.ts`), ничего никуда не уходит.
  Когда владелец выберет, куда приходят заявки (почта, MAX), меняется только `sendOrder` в этом файле.
- Шрифты свои (`@fontsource`), без Google Fonts: данные посетителей не уходят за границу, как и написано в политике.
- Сначала телефон: любое изменение вёрстки проверять на 360, 390 и 414 px, страница не должна прокручиваться вбок.

## Откуда берутся данные и фото

Источник один: собранная демо-версия в корне репозитория. `npm run dev` и `npm run build` сначала запускают
`scripts/import.mjs`, он берёт:

- из `katalog.html` разделы, фильтры, коллекции, юридические тексты и реквизиты (те же данные, что видит покупатель в демо);
- из пакетов `<фабрика>/s-*.json`, `l-*.json`, `torex/k-*.json` фото дверей и комплектации (base64) и раскладывает их файлами
  в `static/foto/`;
- из `photos/` фото главной.

Всё это в git не попадает (`.gitignore`): фото уже лежат в репозитории пакетами, второй копии не нужно.
Поменялись данные фабрик (`web/*.json`) — сначала пересборка демо (`tools/build31.mjs`, на компьютере владельца), потом `npm run build` здесь.
Когда демо уйдёт на покой, нормализация из `tools/build31.mjs` переедет в `scripts/` этой папки.

## Как запустить

Нужен Node.js 22.17 или новее.

```bash
cd app
npm install
npm run dev        # http://localhost:5173
npm run build      # готовый сайт в app/build/
npm run preview    # посмотреть собранный сайт
npm run check      # проверка типов и Svelte
```

Если сайт лежит не в корне домена, путь задаётся при сборке: `BASE_PATH=/portal npm run build`.

## Хостинг

Хостинг продакшна ещё не выбран. Сейчас стоит `@sveltejs/adapter-static`: `npm run build` даёт обычную папку `build/`
со статическими страницами (около 90 МБ, почти всё фото), её можно выложить куда угодно: свой сервер с nginx, Яндекс Object Storage,
Netlify, Vercel, GitHub Pages. Когда появится сервер для заявок, адаптер меняется в `vite.config.ts` на адаптер площадки
(`adapter-node`, `adapter-vercel` и т. п.), страницы и данные при этом не меняются.

## Как устроен код

- `src/routes/` страницы, `+page.server.ts` у каждой отдаёт ей только нужные данные (каталог целиком в браузер не уходит).
- `src/lib/server/catalog.ts` каталог на сервере сборки, `src/lib/server/generated/` то, что записал импорт.
- `src/lib/components/` шапка, подвал, форма заявки, крупный просмотр, комплектация Торекса, окно cookie.
- `src/lib/styles/` стили демо: `base.css` общий, `home.css` и `catalog.css` действуют внутри `.pg-home` и `.pg-cat`,
  чтобы правила главной и каталога не спорили между собой. `app.css` дополнения этой версии.
- Импорты внутри проекта через `#lib/...` с расширением файла (`#lib/text.ts`), так требует SvelteKit 3.
